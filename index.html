How auto-update works — the main logic (read this first)

A visual change alone never updates code. The browser page (DOM) is only memory. Refresh and it is gone. That is why VisBug, SitePeel and Edit Page lose changes.

Auto-update needs 3 steps, and this tool does all 3:

  1. Record the change as data, not pixels. Every edit becomes: file + selector + what changed + old value → new value.
    Example: index.html, h1.hero-title, color, #000000 → #ff0000
  2. Patch the source file. Find that same element in the real index.html code (by its selector) and change it there — text, or an inline style. The source file is the truth, not the screen.
  3. Commit the file to GitHub. Send the new file to GitHub with the GitHub Contents API. GitHub Pages then rebuilds (about 1 minute) and the live site shows the change.

Example: you change a heading from black to red.
Screen: h1 turns red.
Code: <h1 class="hero-title" style="color: #ff0000;"> is written into index.html.
GitHub: index.html is committed to main. Pages rebuilds. Live link updates.

Move (drag): dragging records a transform: translate(x, y) style on that element, and that style is written into the code the same way.

v1 limit, stated plainly: style and text changes are saved as inline styles / text inside index.html only. The tool does not yet rewrite a separate style.css file. Inline style wins over the CSS file, so the live page looks right, and the change is in the code.

Token is stored only in this browser (localStorage). It is sent only to api.github.com, never to anyone else. Never paste it in chat. Create one at: https://github.com/settings/tokens — make a fine-grained token, pick only the repo you will edit, give it Contents Read and write. Without a token the tool still works in log-only mode: edits show in the preview and in the Change Log, but nothing is saved to GitHub.
